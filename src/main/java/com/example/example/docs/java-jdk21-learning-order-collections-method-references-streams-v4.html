Understand for Every Collection

  • Ordering — Does the collection preserve insertion order, sorted order, or no guaranteed order?
  • Duplicates — Are duplicate elements or duplicate keys allowed?
  • Null support — Does it allow null elements, null keys, or null values?
  • Sorting behavior — Is sorting automatic, natural-order based, Comparator-based, or manual?
  • Typical use case — When should this collection be preferred over similar alternatives?
  • Thread-safety basics — Is it thread-safe by default, synchronized, concurrent, or intended for single-threaded use?

Comparable & Comparator Q&A

Natural Ordering, Custom Ordering & Internal Calls

Q1. When does Java internally call Comparable.compareTo()?

Answer: Java internally calls compareTo() when an API needs natural ordering and no Comparator is supplied.

No Comparator
    ↓
Natural ordering
    ↓
Comparable.compareTo()

Common examples:

  • TreeSet without Comparator
  • TreeMap without Comparator
  • Collections.sort(list)
  • List.sort(null)
  • Stream.sorted()
  • Arrays.sort(objectArray)
  • PriorityQueue without Comparator

Q2. Is compareTo() used only by TreeSet?

Answer: No. Any Java API that needs natural ordering can use Comparable.compareTo().

Q3. When does TreeSet call compareTo()?

Answer: When you create a TreeSet without passing a Comparator and the element type implements Comparable.

TreeSet<Employee> employees = new TreeSet<>();

Employee implements Comparable<Employee>
        ↓
TreeSet internally compares elements
        ↓
Employee.compareTo(other)

Q4. What happens if compareTo() returns 0 inside TreeSet?

Answer: The two elements are treated as equal for ordering, so the second element is not added.

compareTo() == 0
        ↓
TreeSet treats elements as duplicates

Example:

record Employee(String name, int salary)
        implements Comparable<Employee> {

    @Override
    public int compareTo(Employee other) {
        return Integer.compare(salary, other.salary);
    }
}

If Ada and Grace both have salary 100, salary-only comparison returns 0, so only one remains in the TreeSet.

Q5. When does Stream.sorted() call compareTo()?

Answer: When you call the no-argument form stream.sorted() and the stream elements have a natural order through Comparable.

Stream<Version>
    ↓
sorted()
    ↓
Version implements Comparable<Version>
    ↓
Version.compareTo(other)

Q6. What is the difference between sorted() and sorted(comparator)?

stream.sorted()
→ natural order
→ Comparable.compareTo()

stream.sorted(comparator)
→ custom order
→ Comparator.compare()

Q7. What does List.sort(null) mean?

Answer: Passing null means: use the elements' natural ordering.

list.sort(null)
    ↓
natural ordering
    ↓
Comparable.compareTo()

Q8. When does Comparator.compare() get used?

Answer: When you explicitly provide a Comparator.

students.sort(
    Comparator.comparing(Student::name)
);

students.stream()
        .sorted(Comparator.comparing(Student::name))
        .toList();

Then Java uses the comparator's comparison logic instead of the natural ordering.

Q9. What is the main difference between Comparable and Comparator?

Comparable Comparator
Defines natural/default ordering Defines custom/external ordering
compareTo() compare()
Usually implemented by the class itself Usually defined outside the class or with lambda/method reference
Normally one natural order Can define many different orderings

Q10. What is the easiest rule to remember?

Java needs ordering
        ↓

Was a Comparator supplied?

YES
→ Comparator.compare()

NO
→ natural ordering
→ Comparable.compareTo()
Core memory rule: sorted(), List.sort(null), natural-order TreeSet, natural-order TreeMap, Collections.sort(), object-array Arrays.sort(), and natural-order PriorityQueue rely on Comparable.compareTo(). If you explicitly supply a Comparator, Java uses that comparison rule instead.
Important Comparator Methods

Comparator Methods — Purpose, Explanation & Examples

Method Purpose Explanation
compare(a, b) Compare two objects Returns negative, zero, or positive depending on ordering.
naturalOrder() Natural ascending order Uses the object's Comparable.compareTo().
reverseOrder() Natural descending order Reverse of the object's natural ordering.
comparing(...) Compare by object field/key Extracts a key from each object and compares the extracted keys.
comparingInt(...) Compare by int field Primitive-specialized comparison that avoids boxing int to Integer.
comparingLong(...) Compare by long field Primitive-specialized comparison for long values.
comparingDouble(...) Compare by double field Primitive-specialized comparison for double values.
thenComparing(...) Secondary comparison Used when the previous comparison returns 0.
thenComparingInt(...) int tie-breaker Secondary comparison using an int field.
thenComparingLong(...) long tie-breaker Secondary comparison using a long field.
thenComparingDouble(...) double tie-breaker Secondary comparison using a double field.
reversed() Reverse existing comparator Converts ascending order to descending or vice versa.
nullsFirst(...) Put null values first Wraps another comparator and safely handles null by placing null before non-null values.
nullsLast(...) Put null values last Wraps another comparator and safely handles null by placing null after non-null values.

1. compare(a, b)

The core comparison method of Comparator.

Comparator<Integer> comparator = Integer::compare;

int result = comparator.compare(10, 20);
  
result < 0  → first comes before second
result == 0 → equal in ordering
result > 0  → first comes after second

2. Comparator.naturalOrder()

Uses the natural ordering defined by Comparable.compareTo().

Comparator<String> comparator =
        Comparator.naturalOrder();
  
naturalOrder()
→ Comparable.compareTo()

3. Comparator.reverseOrder()

Uses reverse natural ordering.

Comparator<Integer> comparator =
        Comparator.reverseOrder();
  
Natural: 1, 2, 3
Reverse: 3, 2, 1

4. Comparator.comparing(...)

Creates a Comparator by extracting an object field/key.

Comparator<Student> byName =
        Comparator.comparing(Student::name);
  
Student
   ↓
extract name
   ↓
compare String values

5. Comparator.comparingInt(...)

Use when the comparison key is primitive int.

Comparator<Student> byId =
        Comparator.comparingInt(Student::id);
  
Student → int

6. Comparator.comparingLong(...)

Use when the comparison key is primitive long.

Comparator<Employee> byEmployeeNumber =
        Comparator.comparingLong(Employee::employeeNumber);

7. Comparator.comparingDouble(...)

Use when the comparison key is primitive double.

Comparator<Employee> bySalary =
        Comparator.comparingDouble(Employee::salary);

8. thenComparing(...)

Used as a tie-breaker when the first comparison is equal.

Comparator<Student> comparator =
        Comparator.comparing(Student::name)
                  .thenComparing(Student::city);
  
First compare name

If name is equal
    ↓
compare city

9. thenComparingInt(...)

Comparator<Student> comparator =
        Comparator.comparing(Student::name)
                  .thenComparingInt(Student::id);

Meaning: sort by name first, then by id if names are equal.

10. thenComparingLong(...)

Comparator<Employee> comparator =
        Comparator.comparing(Employee::department)
                  .thenComparingLong(Employee::employeeNumber);

11. thenComparingDouble(...)

Comparator<Employee> comparator =
        Comparator.comparing(Employee::department)
                  .thenComparingDouble(Employee::salary);

12. reversed()

Reverses an already-created comparator.

Comparator<Employee> bySalaryDesc =
        Comparator.comparingDouble(Employee::salary)
                  .reversed();
  
ascending
   ↓ reversed()
descending

13. nullsFirst(...)

Safely handles null and places null values first.

Comparator<String> comparator =
        Comparator.nullsFirst(
                Comparator.naturalOrder()
        );
  
Input:
Zuri
null
Ada

Sorted:
null
Ada
Zuri

14. nullsLast(...)

Safely handles null and places null values last.

Comparator<String> comparator =
        Comparator.nullsLast(
                Comparator.naturalOrder()
        );
  
Sorted:
Ada
Zuri
null

Important Combined Example

Comparator<Employee> comparator =
        Comparator.comparing(Employee::department)
                  .thenComparingDouble(Employee::salary)
                  .thenComparing(Employee::name);
  
1. Compare department
2. If equal, compare salary
3. If equal, compare name

Department Ascending + Salary Descending

Comparator<Employee> comparator =
        Comparator.comparing(Employee::department)
                  .thenComparing(
                      Comparator.comparingDouble(Employee::salary)
                                .reversed()
                  );
  
department → ascending
salary     → descending within department

Mastery Test

Your Brain Should Translate Requirements Into Pipelines

Example requirement:

Find the top 3 most common skills among active IT employees earning more than 80,000.

employees
  ↓ filter active
  ↓ filter department == IT
  ↓ filter salary > 80000
  ↓ flatMap skills
  ↓ groupingBy skill + counting
  ↓ entrySet().stream()
  ↓ sorted by count descending
  ↓ limit 3
  ↓ map skill
  ↓ toList
If you can mentally identify this pipeline before writing code, you have reached a strong practical Stream level.
