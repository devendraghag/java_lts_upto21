Creational pattern

Builder

Builder helps create an object in clear steps when it has many choices or optional values.

Main thought: “Are there too many construction parameters?”

A long constructor can hide the meaning of each argument. Builder replaces that confusing list with named choices, then returns the finished object from build().

Sandwich analogy: choose bread, filling, and sauce. The counter keeps track of your choices and hands over the sandwich when you finish the order.

Object creation flow

Caller chooses named options
→
Builder stores choices
→
build() validates and creates
→
Caller receives object

Why this name? The builder gradually assembles a product from the choices. The caller describes what it wants; the builder performs the final construction.

The problem it solves

Imagine new Employee(7, "Mira", "Developer", "Pune", 90000, true, null). It is hard to remember what each position means, and optional values make it worse. A builder makes each choice visible:

Employee.builder()
        .id(7)
        .name("Mira")
        .city("Pune")
        .build();

It is useful for objects with many parameters, optional settings, validation rules, or required construction steps. For an object with only a few simple required values, a constructor is usually clearer.

Java and Spring connection

Builder-style APIs appear in Java libraries. Spring's UriComponentsBuilder lets you add URI parts step by step and then build the result. Lombok's @Builder can generate builder code when a project uses Lombok.

Interview one-liner

Builder creates a complex object step by step and keeps construction separate from the code that uses the object.
