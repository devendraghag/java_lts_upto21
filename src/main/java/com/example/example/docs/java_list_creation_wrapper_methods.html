1. List.of(...) — Create an Unmodifiable List Directly

List.of(...) creates a list directly from the values you provide. It is ideal when the values are already known and you do not want callers to add, remove, or replace elements later.

Unmodifiable Fixed Size Ordered Indexed Duplicates Allowed Null Not Allowed
add()Not allowed remove()Not allowed set()Not allowed nullNot allowed DuplicatesAllowed
Important: The list structure is unmodifiable, but if it stores mutable objects, those objects themselves may still be modified.
import java.util.List;

public class ListOfExample {

    public static void main(String[] args) {

        List<String> technologies =
                List.of(
                        "Java",
                        "Spring Boot",
                        "Docker",
                        "Java"
                );

        System.out.println("List: " + technologies);
        System.out.println("Size: " + technologies.size());
        System.out.println("First: " + technologies.get(0));
        System.out.println("Contains Java: "
                + technologies.contains("Java"));

        System.out.println("\nIteration:");
        for (String technology : technologies) {
            System.out.println(technology);
        }

        System.out.println("\nUsing Stream:");
        technologies.stream()
                .filter(value -> value.startsWith("J"))
                .forEach(System.out::println);

        // Not allowed:
        // technologies.add("Kubernetes");
        // technologies.remove("Java");
        // technologies.set(0, "Python");
        // technologies.clear();

        // Null not allowed:
        // List<String> invalid =
        //         List.of("Java", null);

        List<String> empty = List.of();
        List<String> single = List.of("Java");

        System.out.println("\nEmpty: " + empty);
        System.out.println("Single: " + single);
    }
}

2. List.copyOf(collection) — Create an Unmodifiable Snapshot

List.copyOf() takes the current elements from another collection and produces an unmodifiable list. Later structural changes to the original source are not reflected in the returned list.

Unmodifiable Snapshot Fixed Size Ordered Indexed Null Not Allowed
Main idea: Use it when you want to expose a safe read-only snapshot rather than a live view of an existing mutable list.
import java.util.ArrayList;
import java.util.List;

public class ListCopyOfExample {

    public static void main(String[] args) {

        List<String> original = new ArrayList<>();

        original.add("Java");
        original.add("Spring");
        original.add("Docker");

        List<String> copy =
                List.copyOf(original);

        System.out.println("Original: " + original);
        System.out.println("Copy    : " + copy);

        original.add("Kubernetes");
        original.remove("Spring");

        System.out.println("\nAfter modifying original:");
        System.out.println("Original: " + original);
        System.out.println("Copy    : " + copy);

        // Not allowed:
        // copy.add("AWS");
        // copy.remove("Java");
        // copy.set(0, "Python");

        List<String> withNull =
                new ArrayList<>();

        withNull.add("Java");
        withNull.add(null);

        try {
            List.copyOf(withNull);
        } catch (NullPointerException e) {
            System.out.println(
                    "\nList.copyOf() does not allow null");
        }
    }
}
MethodLater source changes visible?
List.copyOf(list)No — snapshot
Collections.unmodifiableList(list)Yes — live view

3. Arrays.asList(...) — Fixed-Size Array-Backed List

Arrays.asList() creates a List view backed by an array. You may replace existing elements with set(), but you cannot add or remove elements because the size is fixed.

Fixed Size Ordered Indexed set() Allowed Null Allowed Array Backed
Key distinction: Fixed-size does not mean immutable. Element replacement is allowed.
import java.util.Arrays;
import java.util.List;

public class ArraysAsListExample {

    public static void main(String[] args) {

        String[] technologies = {
                "Java",
                "Spring",
                "Docker"
        };

        List<String> list =
                Arrays.asList(technologies);

        System.out.println("Array: "
                + Arrays.toString(technologies));
        System.out.println("List : " + list);

        list.set(1, "Spring Boot");

        System.out.println("\nAfter list.set():");
        System.out.println("Array: "
                + Arrays.toString(technologies));
        System.out.println("List : " + list);

        technologies[0] = "Python";

        System.out.println("\nAfter array change:");
        System.out.println("Array: "
                + Arrays.toString(technologies));
        System.out.println("List : " + list);

        list.set(2, null);
        System.out.println("\nNull allowed: " + list);

        try {
            list.add("Kubernetes");
        } catch (UnsupportedOperationException e) {
            System.out.println("add() not supported");
        }

        try {
            list.remove("Python");
        } catch (UnsupportedOperationException e) {
            System.out.println("remove() not supported");
        }
    }
}

4. Collections.unmodifiableList(list) — Read-Only View

This method wraps an existing list so that callers cannot modify it through the wrapper reference. However, the original backing list may still be changed, and those changes are visible through the wrapper.

Unmodifiable View Backing List Shared Read Only Through Wrapper
Think of it as: the wrapper blocks write operations, but it still looks at the same underlying list.
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

public class UnmodifiableListExample {

    public static void main(String[] args) {

        List<String> original =
                new ArrayList<>();

        original.add("Java");
        original.add("Spring");
        original.add("Docker");

        List<String> readOnly =
                Collections.unmodifiableList(original);

        System.out.println("Original : " + original);
        System.out.println("ReadOnly : " + readOnly);

        original.add("Kubernetes");

        System.out.println(
                "\nAfter original.add():");

        System.out.println("Original : " + original);
        System.out.println("ReadOnly : " + readOnly);

        original.set(0, "Java 21");

        System.out.println(
                "\nAfter original.set():");
        System.out.println("ReadOnly : " + readOnly);

        try {
            readOnly.add("AWS");
        } catch (UnsupportedOperationException e) {
            System.out.println(
                    "\nreadOnly.add() not allowed");
        }

        try {
            readOnly.set(0, "Python");
        } catch (UnsupportedOperationException e) {
            System.out.println(
                    "readOnly.set() not allowed");
        }
    }
}

5. Collections.synchronizedList(list) — Thread-Safe Synchronized Wrapper

This method wraps an existing list and synchronizes its ordinary List operations. It is useful when multiple threads need to share a list and you specifically want the synchronized-wrapper approach.

Thread Safe Synchronized Wrapper Usually Modifiable Behavior Depends on Backing List
Iteration rule: When iterating, synchronize manually on the returned list to protect the entire traversal.
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

public class SynchronizedListExample {

    public static void main(String[] args)
            throws InterruptedException {

        List<Integer> numbers =
                Collections.synchronizedList(
                        new ArrayList<>()
                );

        Thread t1 = new Thread(() -> {
            for (int i = 1; i <= 1000; i++) {
                numbers.add(i);
            }
        });

        Thread t2 = new Thread(() -> {
            for (int i = 1001; i <= 2000; i++) {
                numbers.add(i);
            }
        });

        t1.start();
        t2.start();

        t1.join();
        t2.join();

        System.out.println(
                "Total elements = "
                        + numbers.size());

        numbers.add(3000);
        numbers.set(0, 9999);

        System.out.println(
                "First element = "
                        + numbers.get(0));

        synchronized (numbers) {
            int count = 0;

            for (Integer number : numbers) {

                if (count == 10) {
                    break;
                }

                System.out.println(number);
                count++;
            }
        }
    }
}
If the backing list is fixed-size, the synchronized wrapper remains fixed-size. The wrapper adds synchronization; it does not change the fundamental capabilities of the backing list.

6. Collections.checkedList(list, type) — Runtime Type-Safe Wrapper

Generics normally protect List types at compile time. A checked list adds runtime checking as well, which is useful when raw types, reflection, legacy APIs, or unsafe third-party code may attempt to insert the wrong type.

Runtime Type Check Wrapper Legacy API Protection 
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

public class CheckedListExample {

    public static void main(String[] args) {

        List<String> normalList =
                new ArrayList<>();

        List<String> checkedList =
                Collections.checkedList(
                        normalList,
                        String.class
                );

        checkedList.add("Java");
        checkedList.add("Spring");

        System.out.println(
                "Checked List: " + checkedList);

        try {
            addWrongType(checkedList);
        } catch (ClassCastException e) {

            System.out.println(
                    "\nWrong type rejected at runtime");

            System.out.println(e.getMessage());
        }

        System.out.println(
                "\nFinal List: " + checkedList);
    }

    @SuppressWarnings({"rawtypes", "unchecked"})
    static void addWrongType(List rawList) {

        rawList.add(100);
    }
}
Without the checked wrapper, unsafe raw-type code may corrupt a logically typed collection. With checkedList(), the wrong insertion is rejected immediately.

7. Collections.emptyList() — Empty Unmodifiable List

Use emptyList() when you want an empty List result without returning null. It is especially useful for APIs and methods that may legitimately return no items.

Empty Unmodifiable Size 0 Safe Return Value 
import java.util.Collections;
import java.util.List;

public class EmptyListExample {

    public static void main(String[] args) {

        List<String> result =
                findTechnologies(false);

        System.out.println("Result: " + result);
        System.out.println(
                "Size = " + result.size());
        System.out.println(
                "isEmpty = " + result.isEmpty());

        for (String value : result) {
            System.out.println(value);
        }

        if (result.isEmpty()) {
            System.out.println(
                    "No technologies found");
        }

        try {
            result.add("Java");
        } catch (UnsupportedOperationException e) {
            System.out.println(
                    "Cannot modify emptyList");
        }
    }

    static List<String> findTechnologies(
            boolean dataAvailable) {

        if (!dataAvailable) {
            return Collections.emptyList();
        }

        return List.of(
                "Java",
                "Spring"
        );
    }
}

8. Collections.singletonList(element) — Exactly One Element

This method creates an unmodifiable List containing exactly one element. It is useful when an API expects a List, but you only have one value.

Exactly One Element Unmodifiable Fixed Size = 1 Null Allowed
Collections.singletonList(null) is allowed, while List.of(null) throws NullPointerException.
import java.util.Collections;
import java.util.List;

public class SingletonListExample {

    public static void main(String[] args) {

        List<String> language =
                Collections.singletonList(
                        "Java"
                );

        System.out.println(
                "List: " + language);

        System.out.println(
                "Size: " + language.size());

        System.out.println(
                "First element: "
                        + language.get(0));

        System.out.println(
                "Contains Java: "
                        + language.contains("Java"));

        List<String> nullList =
                Collections.singletonList(null);

        System.out.println(
                "\nSingleton containing null:");
        System.out.println(nullList);

        try {
            language.add("Spring");
        } catch (UnsupportedOperationException e) {
            System.out.println(
                    "\nadd() not allowed");
        }

        try {
            language.set(0, "Python");
        } catch (UnsupportedOperationException e) {
            System.out.println(
                    "set() not allowed");
        }
    }
}

9. Collections.nCopies(n, element) — Same Element Repeated N Times

Collections.nCopies(n, element) creates an unmodifiable List whose size is n and where every position contains the same supplied element.

This is useful when you need repeated default values, placeholders, test data, initial display values, or a simple repeated sequence without manually calling add() many times.

Unmodifiable Fixed Size Ordered Indexed Duplicates Allowed Null Allowed Same Reference Repeated
Very important: If element is a mutable object, nCopies() does not clone it N times. Every position refers to the same object.
import java.util.Collections;
import java.util.List;

public class NCopiesExample {

    public static void main(String[] args) {

        List<String> technologies =
                Collections.nCopies(
                        5,
                        "Java"
                );

        System.out.println(technologies);

        System.out.println(
                "Size = "
                        + technologies.size());

        System.out.println(
                "Index 0 = "
                        + technologies.get(0));

        System.out.println(
                "Index 4 = "
                        + technologies.get(4));

        System.out.println(
                "Frequency of Java = "
                        + Collections.frequency(
                                technologies,
                                "Java"
                        )
        );

        try {
            technologies.add("Spring");
        } catch (UnsupportedOperationException e) {
            System.out.println(
                    "add() not allowed");
        }

        try {
            technologies.set(0, "Python");
        } catch (UnsupportedOperationException e) {
            System.out.println(
                    "set() not allowed");
        }

        List<String> nullValues =
                Collections.nCopies(
                        3,
                        null
                );

        System.out.println(
                "Null values: "
                        + nullValues);
    }
}

Mutable Object Example

import java.util.Collections;
import java.util.List;

public class NCopiesObjectExample {

    public static void main(String[] args) {

        Employee employee =
                new Employee("Devendra");

        List<Employee> employees =
                Collections.nCopies(
                        3,
                        employee
                );

        System.out.println(
                "Before: " + employees);

        employee.name =
                "Java Developer";

        System.out.println(
                "After : " + employees);

        System.out.println(
                employees.get(0)
                        == employees.get(1));

        System.out.println(
                employees.get(1)
                        == employees.get(2));
    }
}

class Employee {

    String name;

    Employee(String name) {
        this.name = name;
    }

    @Override
    public String toString() {
        return name;
    }
}

Because every position references the same Employee object, changing that object appears at every position in the List.
