1. Basic idea

First decide what behavior you need, then choose the class.

📚 List

Ordered sequence. Duplicates allowed. Usually index-oriented.

🧩 Set

Uniqueness first. Hash, iteration-order, sorted and enum-specialized variants.

🗺️ Map

Unique keys mapped to values. Hash, linked, tree and concurrent forms.

🚦 Queue / Deque

FIFO, LIFO, priority, delay, blocking and direct-handoff processing.

⚙️ Concurrent

Thread-safe structures with weakly-consistent or snapshot iteration.

🧱 Abstract

Base helper base classes for writing your own Collection/List/Set/Queue/Map.

2. Order patterns explained

These words are used again and again in Java collections.

Insertion order

The collection remembers the order in which you added items.

add A→add B→add C

Loop result: A, B, C

Iteration order

This is the order in which items come back when you use a loop or iterator.

for-each→A, B, C

It can be insertion order, sorted order, priority order, or no guaranteed order.

Encounter order

Encounter order means the order in which elements are seen while you loop through the collection. In simple words: the order returned by a loop, iterator, or stream.

collection→iterator / stream→A, B, C

ArrayList: usually insertion/index order. TreeSet: sorted order. HashSet: no guaranteed order.

Sorted order

Items come back according to comparison rules, not according to the order you inserted them.

add 30add 10add 20

Loop result: 10, 20, 30

Priority order

The queue gives the most important item first according to its comparison rule. But looping through a priority queue is not guaranteed to be fully sorted.

PriorityQueue→peek / poll gives head

Important: iterator order is not guaranteed to be priority-sorted.

No guaranteed order

Java does not promise a fixed loop order. The order may look stable now but can change later.

HashSet→maybe B, A, C

Do not write code that depends on this order.

3. Collection families

Understand the job of each family before choosing a class.

List

Use it when: you need a sequence of items.

0:A1:B2:C

Duplicates are allowed. Position/index is important.

Set

Use it when: every item should be unique.

ABC

Duplicate values are not stored.

Map

Use it when: you need key → value lookup.

1 → A2 → B

Keys are unique. Values may repeat.

Queue

Use it when: items should be processed in a defined order.

A→B→C

That order may be FIFO, priority, delay, or blocking.

Deque

Use it when: you need both front and back operations.

front⇄items⇄back

Useful as both a queue and a stack.

Concurrent collections

Use them when: multiple threads share and change the same collection.

Thread A→Collection←Thread B

Examples include ConcurrentHashMap, blocking queues and copy-on-write collections.

4. How data is stored

The storage method explains why some operations are fast and others are slow.

Resizable array

0:A1:B2:C3:Dcapacity…

ArrayList / Vector / CopyOnWriteArrayList. O(1) index access; middle insertion shifts elements.

Linked nodes

A⇄B⇄C⇄D

LinkedList and linked queues/deques. Cheap end/local relinking; no O(1) numeric indexing.

Hash table

hash(key)→bucket→entry

HashMap / HashSet / ConcurrentHashMap. Hash narrows the search; equality confirms the key.

Tree / skip list

smaller←root/key→larger

TreeMap/TreeSet keep sorted order; skip lists provide sorted concurrent access.

Binary heap

Priority queues. Only the head priority is guaranteed; iteration is not fully sorted.

Copy-on-write

Readers keep snapshots while writers publish a new array.

9. What happens while looping?

Usually detects unsafe structural changes during iteration and may throw ConcurrentModificationException

Typical ordinary collections. An iterator may throw ConcurrentModificationException after incompatible structural modification. This is best-effort bug detection, not thread safety.

Safe during concurrent changes; it may show some new changes and skip others

Typical concurrent collections. Iteration proceeds safely during updates and may reflect some later changes.

Snapshot

CopyOnWrite collections. The iterator sees the exact array version captured when it was created.

Beginner tip: O(1) means normally very fast and does not grow much with collection size. O(n) means Java may need to check many or all elements. O(log n) means it gets slower as data grows, but still stays efficient for large collections.
Performance note: Big-O is the algorithmic model only. Cache locality, object allocation, GC, hash quality, comparator cost, contention, fairness and JVM optimizations can dominate real-world speed.
