Java Collection Categories Reference

A practical classification of the Java Collections Framework, including mutability, sizing, ordering, concurrency, access pattern, data structure, and specialized collection categories.

Important Note

Collection is the root interface for structures such as List, Set, and Queue. Map belongs to the Java Collections Framework, but Map does not extend Collection.

1. Modifiable Collection

Meaning: Elements can be added, removed, replaced, or otherwise changed after creation.

ArrayListLinkedListHashSetTreeSetHashMapArrayDequeConcurrentHashMap

2. Unmodifiable Collection

Meaning: The reference cannot be used to perform structural modifications such as add(), remove(), or put().

Examples: List.of(), Set.of(), Map.of(), Collections.unmodifiableList(), Collections.unmodifiableSet(), Collections.unmodifiableMap().

Important: An unmodifiable wrapper can still reflect changes made directly to its backing collection.

3. Immutable Collection

Meaning: The collection cannot change after creation. Its structure is permanently fixed.

Examples: List.of(), Set.of(), Map.of(), List.copyOf(), Set.copyOf(), Map.copyOf().

4. Resizable Collection

Meaning: The number of elements can grow or shrink dynamically.

Examples: ArrayList, LinkedList, HashSet, TreeSet, PriorityQueue, HashMap.

5. Fixed-Size Collection

Meaning: The number of elements or capacity is fixed.

Examples: Arrays.asList(), List.of(), Set.of(), Map.of(), ArrayBlockingQueue.

6. Ordered Collection

Meaning: The collection provides a defined iteration order, such as insertion order, natural order, or enum declaration order.

Examples: ArrayList, LinkedList, LinkedHashSet, TreeSet, LinkedHashMap, TreeMap, EnumSet.

7. Unordered Collection

Meaning: No stable iteration order should be relied upon.

Examples: HashSet, HashMap, Hashtable, ConcurrentHashMap.

8. Sorted Collection

Meaning: Elements or keys are maintained according to natural ordering or a supplied Comparator.

Examples: TreeSet, TreeMap, ConcurrentSkipListSet, ConcurrentSkipListMap.

9. Indexed Collection

Meaning: Elements can be accessed by numeric position using methods such as get(index).

Examples: ArrayList, LinkedList, Vector, Stack, CopyOnWriteArrayList, Arrays.asList().

10. Non-Indexed Collection

Meaning: Elements are not retrieved by numeric index.

Examples: HashSet, TreeSet, PriorityQueue, HashMap.

11. Duplicate-Allowing Collection

Meaning: Multiple equal elements may exist in the same collection.

Examples: All major List implementations and most Queue/Deque implementations.

12. Duplicate-Not-Allowed Collection

Meaning: Duplicate elements are rejected according to equality or ordering rules.

Examples: HashSet, LinkedHashSet, TreeSet, EnumSet, CopyOnWriteArraySet, ConcurrentSkipListSet.

For Map, duplicate keys are not allowed, although duplicate values are allowed.

13. Null-Allowing Collection

Meaning: One or more null elements, keys, or values may be stored.

Examples: ArrayList, LinkedList, HashSet, LinkedHashSet, HashMap, LinkedHashMap, WeakHashMap.

14. Null-Not-Allowed Collection

Meaning: Inserting null is prohibited.

Examples: ArrayDeque, PriorityQueue, EnumSet, ConcurrentHashMap, ConcurrentSkipListSet, ConcurrentLinkedQueue, List.of(), Set.of(), Map.of().

15. Thread-Safe Collection

Meaning: Designed so multiple threads can access the structure safely without external synchronization for ordinary supported operations.

Examples: Vector, Stack, ConcurrentHashMap, CopyOnWriteArrayList, ConcurrentLinkedQueue, blocking queues.

16. Non-Thread-Safe Collection

Meaning: Concurrent modification from multiple threads requires external coordination.

Examples: ArrayList, LinkedList, HashSet, TreeSet, HashMap, TreeMap, ArrayDeque.

17. Synchronized Collection

Meaning: Access is serialized using synchronization.

Examples: Vector, Stack, Hashtable, Collections.synchronizedList(), Collections.synchronizedSet(), Collections.synchronizedMap().

18. Concurrent Collection

Meaning: Designed specifically for scalable access by multiple threads, usually with finer-grained coordination than legacy synchronized collections.

Examples: ConcurrentHashMap, ConcurrentSkipListMap, ConcurrentLinkedQueue, CopyOnWriteArrayList, LinkedBlockingQueue.

19. Blocking Collection

Meaning: Operations can wait until data or capacity becomes available.

Examples: ArrayBlockingQueue, LinkedBlockingQueue, LinkedBlockingDeque, PriorityBlockingQueue, DelayQueue, SynchronousQueue, LinkedTransferQueue.

20. Non-Blocking Collection

Meaning: Core operations generally do not wait for another thread to release a monitor or make data available.

Examples: ConcurrentLinkedQueue, ConcurrentLinkedDeque, and many ordinary operations of ConcurrentHashMap.

21. Fail-Fast Collection

Meaning: Iterators detect incompatible structural modifications and may throw ConcurrentModificationException.

Examples: ArrayList, LinkedList, HashSet, TreeSet, HashMap, TreeMap, ArrayDeque.

Fail-fast behavior is best-effort and should not be used as a thread-safety mechanism.

22. Fail-Safe / Weakly Consistent / Snapshot Collection

Meaning: Iteration does not behave like ordinary fail-fast iterators. Java documentation usually uses the more precise terms snapshot or weakly consistent.

Snapshot: CopyOnWriteArrayList, CopyOnWriteArraySet.

Weakly consistent: ConcurrentHashMap, ConcurrentLinkedQueue, ConcurrentSkipListMap.

23. Sequential-Access Collection

Meaning: Efficient access typically follows links sequentially rather than jumping directly to an index.

Primary example: LinkedList.

24. Random-Access Collection

Meaning: Indexed access is efficient and typically near constant time.

Examples: ArrayList, Vector, Stack, CopyOnWriteArrayList, Arrays.asList().

25. FIFO Collection

Meaning: First In, First Out. The earliest inserted element is normally processed first.

Examples: ArrayDeque, LinkedList, ConcurrentLinkedQueue, ArrayBlockingQueue, LinkedBlockingQueue.

26. LIFO Collection

Meaning: Last In, First Out. The most recently inserted element is processed first.

Examples: ArrayDeque, LinkedList, Stack, ConcurrentLinkedDeque.

For modern Java stack behavior, prefer Deque with ArrayDeque instead of legacy Stack.

27. Priority-Based Collection

Meaning: Elements are processed according to priority or ordering rather than insertion time.

Examples: PriorityQueue, PriorityBlockingQueue, DelayQueue.

28. Queue Collection

Meaning: Represents elements waiting to be processed, often using FIFO or priority semantics.

Examples: PriorityQueue, ArrayDeque, LinkedList, ConcurrentLinkedQueue, ArrayBlockingQueue, LinkedBlockingQueue.

29. Deque Collection

Meaning: Double-ended queue. Elements can be inserted and removed from both ends.

Examples: ArrayDeque, LinkedList, ConcurrentLinkedDeque, LinkedBlockingDeque.

30. Set Collection

Meaning: Stores unique elements.

Examples: HashSet, LinkedHashSet, TreeSet, EnumSet, CopyOnWriteArraySet, ConcurrentSkipListSet.

31. List Collection

Meaning: Ordered, positional sequence that usually allows duplicates.

Examples: ArrayList, LinkedList, Vector, Stack, CopyOnWriteArrayList.

32. Map Collection Framework Type

Meaning: Stores key-value pairs with unique keys.

Examples: HashMap, LinkedHashMap, TreeMap, Hashtable, WeakHashMap, IdentityHashMap, EnumMap, ConcurrentHashMap, ConcurrentSkipListMap.

33. Sorted Set Collection

Meaning: A set that keeps its elements sorted.

Examples: TreeSet, ConcurrentSkipListSet.

34. Navigable Set Collection

Meaning: A sorted set with navigation operations such as lower(), floor(), ceiling(), and higher().

Examples: TreeSet, ConcurrentSkipListSet.

35. Sorted Map Collection

Meaning: A map whose keys are maintained in sorted order.

Examples: TreeMap, ConcurrentSkipListMap.

36. Navigable Map Collection

Meaning: A sorted map with key-navigation operations such as lowerKey(), floorKey(), ceilingKey(), and higherKey().

Examples: TreeMap, ConcurrentSkipListMap.

37. Hash-Based Collection

Meaning: Uses hash codes to place and locate entries efficiently.

Examples: HashSet, LinkedHashSet, HashMap, LinkedHashMap, Hashtable, WeakHashMap, IdentityHashMap, ConcurrentHashMap.

38. Tree-Based Collection

Meaning: Uses a tree structure, typically a Red-Black Tree, to maintain sorted order.

Examples: TreeSet, TreeMap.

ConcurrentSkipListSet and ConcurrentSkipListMap are sorted, but they are skip-list based rather than tree-based.

39. Array-Based Collection

Meaning: Internally relies mainly on arrays.

Examples: ArrayList, Vector, Stack, ArrayDeque, PriorityQueue, ArrayBlockingQueue, CopyOnWriteArrayList.

40. Linked-Node-Based Collection

Meaning: Uses linked nodes or linked ordering metadata.

Examples: LinkedList, LinkedHashSet, LinkedHashMap, LinkedBlockingQueue, ConcurrentLinkedQueue, ConcurrentLinkedDeque.

41. Copy-On-Write Collection

Meaning: Modification creates a fresh internal copy, making iteration stable and very safe for read-heavy workloads.

Examples: CopyOnWriteArrayList, CopyOnWriteArraySet.

42. Enum-Based Collection

Meaning: Optimized specifically for enum keys or enum elements.

Examples: EnumSet, EnumMap.

43. Identity-Based Collection

Meaning: Compares keys by object identity using == instead of normal equals().

Example: IdentityHashMap.

44. Weak-Reference Collection

Meaning: Keys are held using weak references, allowing entries to disappear when keys are no longer strongly reachable elsewhere.

Example: WeakHashMap.
