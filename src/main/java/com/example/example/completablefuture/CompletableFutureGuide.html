Java · Async programming

CompletableFuture

A CompletableFuture is a result that may arrive later. You can start work, attach the next step, and combine results without writing every thread by hand.

Easy analogy: a restaurant order ticket

You place an order and get a ticket. The kitchen prepares the food while you do other things. When the food is ready, the next step can serve it, package it, or combine it with another order.

A CompletableFuture<T> is like that ticket: it represents a value of type T that may not be ready yet. A chain of future steps describes what should happen when earlier work finishes.

Start a task
→
Future holds its pending result
→
Next step uses the result
→
join() waits when result is needed

supplyAsync() starts a task that returns a value. runAsync() starts a task that returns no value. join() waits for completion and returns the result.

By default, async methods without an executor use the JDK's common pool. An example later shows how to pass your own executor. See the Java 21 CompletableFuture API.

Easy notes: Future and CompletableFuture

1. What is a Future?

A Future is a promise that a task will give you an answer later. You can ask for the answer with get(). If the task is still working, get() makes your current thread wait.

Think of a parcel receipt: the receipt tells you a parcel is coming. You can check back later, but the old Future does not automatically deliver the next action when the parcel arrives.

2. What did Java 8 add?

Java 8 added CompletableFuture. It can hold a future answer like Future, and it lets you say what should happen after that answer arrives. You can connect steps without calling get() between every step.

Start work
→
When answer arrives, change it
→
Use or print the answer

3. Useful method names in plain English

  • supplyAsync(): run work that gives back a value.
  • runAsync(): run work that does not give back a value.
  • thenApply(): take the answer and change it.
  • thenAccept(): take the answer and do something with it, such as print it.
  • thenCompose(): use one answer to start another future task.
  • thenCombine(): join the answers from two separate tasks.
  • exceptionally(): provide a backup answer if a task fails.

4. Small example

CompletableFuture.supplyAsync(() -> "Mira")
    .thenApply(String::toUpperCase)       // Change Mira to MIRA
    .thenAccept(System.out::println);     // Print MIRA

The first step produces "Mira". The next step changes it to uppercase. The last step prints it. Each step is attached to the previous one.

5. Quick comparison

FutureCompletableFuture
Usually call get() and wait for the answer.Attach the next action with methods such as thenApply().
Does not have built-in steps for combining results or fallback answers.Can connect tasks, combine results, and handle failures.

Remember: CompletableFuture can still wait if you call get() or join(). Its benefit is that you can connect the work first and wait only when you truly need the final answer.

In Java 8, CompletableFuture implements both Future and CompletionStage. Read the official Future API and CompletableFuture API.

Three useful differences

  • thenApply changes a value; thenCompose starts another future-producing step.
  • thenCombine joins two results; allOf waits for many futures but does not gather their values by itself.
  • Async methods without an explicit executor use the default async executor. Give the method an executor when you need to control the worker pool.

Tip: keep work asynchronous while composing stages. Call join() at the edge of the program when you truly need the result, because it blocks the calling thread until completion.
