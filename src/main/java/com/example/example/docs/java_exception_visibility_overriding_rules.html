Exception + Visibility Rules in Method Overriding

1. Parent method declares NO checked exception

  • Child method cannot introduce a checked exception ❌
  • Child method can declare an unchecked exception ✅
  • Child method can declare no exception ✅

2. Parent method declares a checked exception

  • Child method can declare the same checked exception ✅
  • Child method can declare a narrower/subclass checked exception ✅
  • Child method can declare no exception ✅
  • Child method cannot declare a broader/superclass checked exception ❌
  • Child method cannot introduce a new unrelated checked exception ❌
  • Child method can declare an unchecked exception ✅

3. Parent method declares multiple checked exceptions

  • Child method can declare the same exceptions ✅
  • Child method can declare a subset of those exceptions ✅
  • Child method can declare narrower/subclass exceptions ✅
  • Child method can declare a combination of same + narrower exceptions ✅
  • Child method can declare no exception ✅
  • Child method cannot declare broader checked exceptions ❌
  • Child method cannot introduce unrelated checked exceptions ❌

4. Visibility / Access Modifier Rule

  • Child method can have the SAME visibility ✅
  • Child method can have WIDER / MORE accessible visibility ✅
  • Child method cannot have NARROWER / LESS accessible visibility ❌

Visibility Order

private < default (package-private) < protected < public

Important

  • private methods cannot be overridden ❌
  • private methods are not inherited by the child class
  • A default / package-private method can be overridden only when the child class has access to it, typically when both classes are in the same package.

Golden Rule

Area Allowed Not Allowed
Checked Exception Same, Narrower/Subclass, None Broader/Superclass, Unrelated checked exception
Unchecked Exception Allowed —
Visibility Same, Wider Narrower

Easy Memory Rule

Exception  → Same or Narrower
Visibility → Same or Wider
