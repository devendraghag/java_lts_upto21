Rules at a glance

The practical rules interviewers expect you to know.

Where it works

Local variables only, with an initializer

Use var for a local variable in a method, constructor, initializer block, or loop when its initializer makes the type clear.

var name = "Mina"; // String var count = 3; // int var names = new ArrayList<String>(); // ArrayList<String>

It also works for enhanced for variables, traditional for loop variables, and try-with-resources variables.

Where it does not

Not for fields, method parameters, or return types

class Example { var field = 5; // NOT allowed: field var method() { return 5; } // NOT allowed: return type void run(var value) {} // NOT allowed: ordinary parameter }

Java 11 added var for parameters of implicitly typed lambda expressions. That is the special parameter exception.

Type inference

The initializer determines a real, fixed type

var amount = 12; // int, not Integer amount = 20; // okay // amount = "twenty"; // compile-time error

The variable can be reassigned if it is not final, but only with a value compatible with its inferred type. var itself does not mean immutable.

Style

Use it when it makes the code easier to read

var customer = findCustomer(id); can be clear when the method name or nearby code makes the type obvious. If the type is important and unclear, write the explicit type. Avoid using var just to shorten every declaration.

Code practice

Predict the inferred type or explain why the declaration is rejected.

Practice 01 · inferred type

What is the type of each variable?

var x = 10; var y = 10.0; var names = List.of("Ana", "Bo");

x is int, y is double, and names is List<String>. These types are inferred at compile time.

Practice 02 · diamond operator

What type is inferred here?

var items = new ArrayList<>(); items.add("hello");

With var, the initializer is typed without an assignment target. The diamond therefore infers ArrayList<Object> here, so items.add("hello") is allowed but the list is not inferred as ArrayList<String>. Prefer new ArrayList<String>() or an assignment target such as List<String> items = new ArrayList<>() when you need that element type.

Practice 03 · lambda

Which lambda declarations are valid in Java 11+?

(var a, var b) -> a + b (var a, b) -> a + b (var a, int b) -> a + b

Only the first is valid. In an implicitly typed lambda, either omit parameter types or write var for every parameter. You cannot mix var, omitted types, and explicit types in one parameter list.

Practice 04 · tricky declaration

Which declarations compile?

var a = new int[]{1, 2}; var b = {1, 2}; var c = (String s) -> s.length();

a compiles and is int[]. b is invalid because an array initializer needs an explicit array type. c is invalid because a lambda needs a target functional-interface type; var cannot infer its type from that initializer alone.
