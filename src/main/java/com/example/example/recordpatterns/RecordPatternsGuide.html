1. Overview

A record is a compact way to declare a class whose main purpose is to carry a fixed set of data. A record pattern lets code test a record’s type and unpack its components in one pattern.

Record declaration

record Point(int x, int y) { }

Declares a record with two components, accessors, a canonical constructor, and value-based equals, hashCode, and toString.

Record pattern

if (value instanceof Point(int x, int y)) {
    System.out.println(x + y);
}

Checks that value is a Point and binds its components to local variables.

Keep the terms separate: records are a kind of class declaration. Record patterns are a language feature for matching and deconstructing instances of record classes.

2. What a record provides

This declaration:

record Person(String name, int age) { }

is roughly equivalent to a final class with private final fields, a constructor, accessors named after the components, and value-based implementations of equals, hashCode, and toString.

Person person = new Person("Asha", 28);

System.out.println(person.name()); // Asha
System.out.println(person.age());  // 28
System.out.println(person);        // Person[name=Asha, age=28]

public record User(String name) { } // public top-level record
record InternalUser(String name) { } // package-private top-level record

class Container {
    private record Credentials(String username) { }
    protected record Result(int code) { }
}
  • Every record is implicitly final; writing final explicitly is allowed but redundant.
  • abstract, sealed, and non-sealed are not allowed on a record.
  • Record components do not take access modifiers. Their generated fields are private final, and their accessors are public.
  • A canonical constructor must be at least as accessible as its record. A public record requires a public canonical constructor.

3. Constructors, validation, and immutability

Compact constructor

Use a compact canonical constructor when validating or normalizing components. Java assigns the constructor parameters to the fields after the compact constructor body completes.

record Person(String name, int age) {
    public Person {
        if (name == null || name.isBlank()) {
            throw new IllegalArgumentException("name is required");
        }
        if (age < 0) {
            throw new IllegalArgumentException("age cannot be negative");
        }
        name = name.trim();
    }
}

Explicit canonical constructor

You can also write the full canonical constructor when you need explicit assignments:

record Point(int x, int y) {
    public Point(int x, int y) {
        this.x = x;
        this.y = y;
    }
}
Records are shallowly immutable. Their component fields cannot be reassigned after construction, but a component can refer to a mutable object. For example, a record holding a List does not automatically make that list immutable. Copy mutable inputs when the API requires defensive ownership.

Useful rules

  • A record is implicitly final and extends java.lang.Record.
  • A record cannot extend another class, but it can implement interfaces.
  • Instance state is described by the record header; additional instance fields are not allowed.
  • Records can declare static fields, static methods, instance methods, and constructors.
  • There are no generated setters.

4. Record patterns in JDK 21

Record patterns are finalized in Java 21. A record pattern names a record type and provides a nested pattern for each component.

record Point(int x, int y) { }

Object value = new Point(3, 4);

if (value instanceof Point(int x, int y)) {
    System.out.println("x=" + x + ", y=" + y);
}

The pattern succeeds only when the value has a compatible record type and its component patterns match. On success, x and y are in scope inside the matching branch.

Before record patterns: code often checked the type, cast the value, and called each accessor separately. A record pattern combines the type test and component extraction.

5. Record patterns with instanceof

Use instanceof when one branch handles a matching record and other values can follow normal control flow.

record Point(int x, int y) { }

static int manhattanDistance(Object value) {
    if (value instanceof Point(int x, int y)) {
        return Math.abs(x) + Math.abs(y);
    }
    return -1;
}

Component types come from the record declaration. You may write their types explicitly or use var to infer them:

if (value instanceof Point(var x, var y)) {
    System.out.println(x + y);
}

Use explicit types when they make the code easier to read. Use var when the component types are obvious or the pattern is nested and explicit type names would add noise.

6. Record patterns in switch

A switch can select behavior based on a record’s type and its component values.

record Point(int x, int y) { }

static String describe(Object value) {
    return switch (value) {
        case Point(int x, int y) -> "Point at (" + x + ", " + y + ")";
        default -> "Not a point";
    };
}

Record patterns can appear alongside other supported case patterns, including type patterns and constants. The compiler checks that pattern variables are available only where they are definitely matched.

7. Nested record patterns

If a record component is itself a record, nest another record pattern to unpack it in the same match.

record Point(int x, int y) { }
record Rectangle(Point upperLeft, Point lowerRight) { }

static String describe(Object value) {
    return switch (value) {
        case Rectangle(
                Point(int left, int top),
                Point(int right, int bottom)) ->
                "Corners: (" + left + ", " + top + ") and ("
                        + right + ", " + bottom + ")";
        default -> "Not a rectangle";
    };
}

This is useful when the shape of the data matters to the decision being made. Avoid deeply nested patterns when naming intermediate values would make the code clearer.

8. Guards and null handling

Guarded patterns

Add a when guard when the record type and component patterns match, but the branch should apply only if an extra condition is true.

return switch (value) {
    case Point(int x, int y) when x == y -> "On the diagonal";
    case Point(int x, int y) when x > y  -> "Below the diagonal";
    case Point(int x, int y)              -> "Above the diagonal";
    default                               -> "Not a point";
};

Case labels are considered in order. Put more specific guarded cases before the unguarded case for the same record pattern.

Null is explicit in switch

A record pattern does not match null. An instanceof test against null is false. A switch whose selector is null throws NullPointerException unless the switch has a case null label.

String result = switch (value) {
    case null -> "No value";
    case Point(int x, int y) -> "Point: " + x + ", " + y;
    default -> "Other value";
};

9. Record patterns with sealed hierarchies

Records work naturally as implementations of sealed interfaces. When a switch covers every permitted subtype, it can be exhaustive without a default branch.

sealed interface Shape permits Circle, Rectangle { }
record Circle(double radius) implements Shape { }
record Rectangle(double width, double height) implements Shape { }

static double area(Shape shape) {
    return switch (shape) {
        case Circle(double radius) -> Math.PI * radius * radius;
        case Rectangle(double width, double height) -> width * height;
    };
}

If a permitted subtype is added later, the compiler can identify switches that need another case.

10. Common pitfalls

MisunderstandingCorrect behavior
“A record is automatically deeply immutable.”Only component fields are fixed. Referenced mutable objects may still change.
“Record accessors are JavaBean getters.”Accessors use the component name, such as age().
“A record can extend a base class.”Records are final and already extend java.lang.Record; they may implement interfaces.
“A record pattern is just a record declaration.”The declaration defines the data type; the pattern matches and extracts components.
“A switch default branch matches null.”Null needs an explicit case null; otherwise a switch on null throws.
“Every record pattern must name each component type.”var component patterns can infer those types.

11. Interview questions and answers

1. What is a Java record?

A restricted class designed to model data as a fixed set of components. The compiler supplies component fields, accessors, a canonical constructor, and value-oriented equals, hashCode, and toString implementations.

2. What members does the compiler derive from a record header?

For each component it derives a private final field and a public accessor, and it provides a canonical constructor plus implementations of equals, hashCode, and toString, unless you explicitly provide compatible implementations.

3. Are records immutable?

They are shallowly immutable: component fields are final, but an object referenced by a component can be mutable. Use defensive copies when you need to prevent external mutation of referenced data.

4. Can a record extend a class or implement an interface?

A record cannot extend another class; it implicitly extends java.lang.Record and is final. It can implement one or more interfaces.

5. What is the canonical constructor?

It is the constructor whose parameters correspond to all record components in declaration order. It is the constructor used to initialize the record state and can be written explicitly or in compact form.

6. What is a compact constructor?

A concise form of the canonical constructor. It lets you validate or normalize the implicitly declared component parameters; the compiler performs the component field assignments after the body.

7. Can a record have extra instance fields or setters?

No extra instance state is allowed beyond its components, and the generated component fields are final. Records do not get setters. Static fields and methods are allowed.

8. How are record accessors named?

They use the component name: a component declared as String name has an accessor name(), not getName().

9. What does a record pattern do?

It checks a value against a record type and recursively matches the record components. Successful matching makes the extracted component values available as pattern variables.

10. Where can record patterns be used in Java 21?

They can be used with instanceof and as patterns in switch labels. They can also be nested to match record-valued components.

11. What is a guarded pattern?

A pattern followed by a when condition. The pattern first matches and binds its variables; the guard then decides whether that case applies.

12. How does a record pattern behave with null?

It does not match null. An instanceof check returns false for null; a switch on null needs an explicit case null or it throws NullPointerException.

13. How do records help with sealed types?

Records can be permitted implementations of a sealed interface. A switch can deconstruct each permitted record type, and the compiler can check that all permitted alternatives are covered.

14. When should you use a record instead of a regular class?

Use a record when the type’s primary purpose is to represent data with a stable set of components and value-based equality. Use a regular class when you need mutable identity, inheritance from another class, or additional instance state.
